# 资源与恢复

## 隔离边界

当前共同机制在指定测试环境中创建本次专属资源，不为每次测试自动建库。数据库、服务和专用账号由环境预先准备；独立标记、身份绑定和所有权核验属于应用层数据隔离，不等于数据库实例隔离。

资源适配器必须依据项目真实 API 实现，不套用另一个项目的字段、路由或业务码。已支持的资源类型、依赖关系和限制由项目说明登记；资源清单存在不代表任意业务都能回滚。

## 写前登记与清理

1. 在首次登录或业务写入前检查显式 `FLOW_ALLOW_WRITE=true`，流程同步声明 ALLOW_WRITE 参数与写入 fixture。
2. 为本次资源生成唯一业务键；检查冲突，已有资源不接管。
3. 请求创建前，将意图写入 `.local/api-resources/<env>/<资源运行编号>.json`。文件权限 0600，目录限制访问，不保存凭据或完整响应。
4. 返回成功后补充资源 ID；清单绑定环境、API/web 地址、操作者、资源类型、唯一键及必要父级。
5. finally 按依赖逆序清理，每项删除前核对精确身份、父级、非内置等项目约束，删除后再次查询确认。
6. 清理不可确认则使流程失败并保留材料，不以成功断言、HTTP 200 或会话退出代替清理结果。

创建响应不确定时保留 pending 意图，不重发创建。恢复按本次精确唯一键定位；明确客户端拒绝不能授权清理竞争者创建的记录。已清理资源重新出现、身份变化、重复匹配或查询不完整都应停止。

父子资源按真实依赖处理，未解决子资源不继续删除父级。业务配置恢复应逐项尝试并回读核验；不可逆业务动作使用专用一次性数据，明确不能回滚，不假装纳入通用删除机制。

## 独立恢复

项目接入恢复适配器后提供：

```bash
FLOW_ALLOW_WRITE=true pnpm test:api:cleanup --env local --run-id <资源运行编号>
```

编号取资源错误或私有清单，不使用 batchId/报告 runId。恢复重新校验环境、地址、操作者与资源归属，材料损坏、权限过宽、路径链接越界、未知资源类型或 ID 不匹配时拒绝处理。

重复恢复应为空操作；不按通用前缀批删、不重放创建、不修改既有资源或直接操作数据库。恢复失败保留材料，不与仍在执行的同一次资源操作并发恢复。

## 会话所有权

自建会话由 fixture 在结束时清理；借用的缓存先核验环境、角色、地址、有效期及远端主体，结束时保留，由操作者明确清理。缓存角色名不等于服务端已配置相应权限。

```bash
pnpm test:flows session login --env local --role admin
pnpm test:flows session check --env local --role admin
pnpm test:flows session clear --env local --role admin
pnpm test:flows session recover --env local --role admin
```

人工登录使用独立非持久浏览器，不使用个人 profile。缓存权限 0600，不接受任意 storageState 路径，不静默覆盖已有缓存。匿名流程不继承认证，验证登录本身的流程不能借缓存省略登录。

session clear/recover 处理会话，资源 cleanup 处理业务数据，分别验证、分别保留失败材料。普通登出是否吊销旧 token 由项目产品契约决定，不能统一假定，也不能通过改密或禁用账号伪造清理成功。

## 必要回归

至少验证：未开启写入、错误环境/身份、已有唯一键、写后响应丢失、删除失败、假删除、错误父级/内置资源、损坏或过宽权限材料、链接越界、重复恢复、自建/借用会话及敏感产物扫描。离线故障注入与真实 CLI 合成装配分开记录，均不算真实业务通过。

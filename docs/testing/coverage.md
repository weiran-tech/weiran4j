# 覆盖与验收口径

## 验证层次

| 层次 | 可以说明什么 | 不能据此说明什么 |
| --- | --- | --- |
| 声明、类型、发现、语法检查 | 入口、依赖、数量和配置一致 | 业务请求成功或断言充分 |
| Node 离线回归 | 执行器与步骤能识别指定正常/故障输入 | 真实环境实现正确 |
| Chromium/API 合成回归 | 实际工具进程、fixture、协议接线、证据和恢复装配可用 | 真实业务数据库、外部系统或真实账号可用 |
| 真实环境执行 | 指定提交、环境、数据和身份下的具体流程结果 | 未运行场景、其他版本或全部角色矩阵通过 |

源码迁入、流程已登记、合成通过、历史通过和当前真实通过分别记录。框架通过不能解除业务 blockedReason；旧项目证据不能继承为新项目通过。

## 按业务组织验收

业务定义放在 [docs/biz](../biz/index.md)，按业务域组织，注明适用项目与来源。内容包括角色、资源、状态与规则、正常/拒绝/边界场景、数据前提、清理和未覆盖项。

项目 `tests/docs/coverage.md` 保留具体流程 ID、源码位置、当前覆盖、阻塞和验证记录入口。业务文档引用流程映射，执行证据仍留项目；不把运行报告正文或私有附件复制进公共约定。

一个验收场景至少写清：适用项目、操作者、前提、动作、可观察后置状态与拒绝条件。写操作另说明资源归属和可恢复性。页面与接口判据各自验证，不能以页面隐藏代替服务端拒绝。

## 数量与边界

流程数、工具用例数、请求数、断言数和业务场景数不是同一指标。一个生命周期用例可能包含多次请求；逐接口矩阵会展开许多工具用例。比较覆盖应看场景及边界，不按数量判断完整度。

空列表可以证明空结果契约，不能证明非空数据字段、排序或持久化。匿名拒绝矩阵不能证明登录后授权、租户/资源隔离或完整成功链路。

## 阻塞与历史

缺页面、接口、专用账号或数据时保留真实阻塞原因，继续参与声明和发现检查；不使用 skip、mock 权限或放宽期望冒充业务通过。环境临时不可达应记录实际失败，不能引用历史成功替代。

验证记录注明提交/源码摘要、日期、环境标识、验证层次、选中范围、结果、阻塞项和证据位置；记录非秘密标识，不写凭据。历史事实与阶段状态保持原样，新验证另记。

本仓测试框架作为文档基线，不代表下游项目已经接入或通过验证。`tests/registry.json` 只是本仓流程注册表，不等同跨项目用例管理系统。

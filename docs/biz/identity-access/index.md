# 身份与权限

适用范围：weiran4j system 基座。来源：`tests/docs/coverage.md`、`tests/docs/writing-flows.md`、项目架构与接口契约。以下说明现有业务验收视角，不代表完整身份系统全部场景已经验证。

## 对象与角色

主体是服务端确认的用户身份；用户、角色与菜单权限共同决定可访问资源和操作。本人资料、页面状态与授权快照须对应同一主体。测试缓存的 role 只是隔离标签，不能证明服务端已配置相应权限。

| 身份 | 验收目标 |
| --- | --- |
| 匿名 | 受保护页面回登录；本人、授权快照、退出和核心业务读取接口拒绝访问 |
| 专用管理员 | 真实登录后确认本人、授权快照、Cookie 与 CSRF；结束后正常清理 |
| 临时受限主体 | 独立用户与角色，验证允许、未授予拒绝及同会话撤权 |

不得以管理员代替受限主体；按钮隐藏不能替代服务端授权拒绝。完整受限角色矩阵仍未覆盖。

## 会话与授权判据

成功业务码是数字 `0`，认证使用 HttpOnly Cookie，写请求使用同一上下文的 CSRF。已登录但缺 CSRF 的写请求应按项目安全契约拒绝，不能与匿名或缺业务权限的错误混淆。

普通登出清 Cookie 和本地缓存，不吊销旧 JWT；旧令牌按产品 TTL 到期。测试不得通过改密、禁用账号或递增 token_version 伪造清理。真实登录和退出会留下审计日志。

临时主体获授一个已有读取权限后验证允许请求，未授予的请求拒绝；撤回临时角色授权后，同一会话对应访问被拒，授权快照保持身份一致并改变修订。

## 生命周期与清理

| 对象 | 已编写的验收范围 |
| --- | --- |
| 用户 | 创建、检索、修改、重复用户名、陈旧版本拒绝、删除复查 |
| 角色 | 普通角色资料与菜单授权的共享版本冲突、有用户关联时拒绝删除 |
| 菜单 | 本次禁用目录、父子关系、陈旧版本、防环及非叶删除保护 |

只操作本次唯一标记创建的普通资源，不修改操作者、已有用户或内置角色。权限流程只在临时角色中引用已有权限定义。用户先于角色清理，具体依赖和归属由适配器验证。测试清理的限制不能直接推导为所有产品资源的业务删除规则。

## 流程映射与验证边界

基础流程为 `system/access-boundary`、`system/login-entry`、`system/admin-session`、`system/admin-browser`；生命周期为 `system/user-lifecycle`、`system/role-lifecycle`、`system/menu-lifecycle`；权限变化为 `system/permission-boundary`。

来源覆盖说明记录核心流程已编写、真实业务尚未运行。离线与合成结果不能替代真实环境报告。短信/MFA/SSO、外部身份及完整受限角色组合不从当前流程推断已覆盖。会话和业务资源清理分别验收，公共机制见 [资源与恢复](../../testing/resources.md)。

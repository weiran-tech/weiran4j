# 产品制作与演示

从[版本清单](/versions)选择版本，进入“原型与改动”。页面由 AI 编程工具修改本仓库源码，站内“编辑版本记录”仅维护目标、基线和日期，改动说明由 AI 随源码维护。

## 用 AI 完成一次原型调整

1. 从协作首页选择目标版本，确认已定版基线；同基线页面调整提醒列出其他版本的同页改动，先与对应产品确认范围。
2. 在 AI 编程工具中打开本仓库，让 AI 阅读根目录 `AGENTS.md`。给出版本、端、页面、原来与现在的行为、异常和验收条件。
3. 让 AI 同步实现页面、本版改动说明与 Mock；新增管理端页面登记菜单，新增手机页面登记手机目录。完整／差异目录依赖稳定页面编号，页面改名时保留编号。
4. 本地启动后，先用“差异”逐页验收，再用“完整”检查继承页面与双端流程。切换管理端／手机端时确认仍是目标版本。
5. 运行 lint、test、build 并在浏览器检查；将页面、说明和指南一起提交 PR。评审时生成固定候选，截图标注后将 PDF 上传到版本 Discussion。

可直接交给 AI 的提示词（将示例版本替换为实际版本）：

```text
请先阅读 AGENTS.md，在 v0.8 的已登记基线上调整手机端订单详情。
保留稳定页面编号 mobile-order-detail。
目标：剩余可退金额为 0 时禁用退款按钮，并显示“已全额退款”。
异常：模拟退款失败时保留金额输入，不修改累计已退金额。
验收：正常、空数据、失败场景均可演示；从管理端手机预览和独立手机页均可访问。
同步本版 CHG、Mock 契约和使用指南，检查同基线同页并行改动。
完成后执行 pnpm lint、pnpm test、pnpm build，并检查浏览器布局。
```

版本路径用于隔离构建、浏览与演示数据。开发不同版本时各自使用 Git 分支及对应版本构建；切换网页版本只切换阅读上下文，不把当前源码变成历史实现。旧版本页面继续使用对应归档。

## 写清每项改动

填写页面及位置、原来怎样、修改为怎样、业务规则、异常场景、验收条件。CHG 编号在本版内保持稳定，供评审和研发任务引用。这些内容维护在 `prototype/releases.json`，与页面同一 PR 提交。网页不提供改动记录的新增、修改或删除，也不能通过导入绕过。

## 体验管理端和手机端

先选版本，再选“完整 / 差异”和端。“差异”按业务模块列出本版涉及的页面；“完整”查看该版全部有效页面。页面名称直接打开原型，“改动说明”按钮在当前页打开抽屉；基线继承、同页冲突和历史归档规则见[版本管理与历史](./versions.md)。

手机端预览可直接选页，二维码按需展开。管理端面包屑和页签可在用户菜单的“偏好设置”开启，恢复默认会隐藏这两项。

完成体验后，按[组织评审与结论](./review.md)生成固定候选并组织评审；定稿后按[研发与验收](./delivery.md)交接。

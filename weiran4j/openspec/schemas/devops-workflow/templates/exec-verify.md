## 前置条件:L7 硬闸门

> **逐行照抄 `openspec/project.json` 的 `commands`,一个键一行** —— 那里是唯一事实源,
> 本模板不预填命令串(预填会在 commands 增删时变成假清单)。
> 证据文件名 = 键名 + `.log`,与 `L7/evidence-missing` 的判定一致。

| 检查(commands 的键) | 命令 | 结果 | 证据 |
|---|---|---|---|
|  |  | ☐ 绿 | `evidence/<键名>.log` |

> 证据必须是**代码全部改完之后**跑的:`L7/evidence-fresh` 按 `project.json` 的 `sourcePaths`
> (`weiran-common`、`weiran-system`、`weiran-app`、`web`)整目录 mtime 判定,
> 留完证据再补一行(哪怕只补测试)就全部失效,且各 log 独立判定,须全部重跑。
>
> ⚠️ **`git stash` / `git stash pop` 会刷新这些目录的 mtime,从而作废已留好的全部证据。**
> 下面的基线对比正好要用 stash,所以**顺序是固定的:先取基线,再留证据。**
> 顺序反了,`openspec check` 会报「证据比源码的最后改动早 0 分钟」——
> 而你刚刚才跑完那几条命令,很容易误判成校验器有 bug。

### 红灯的归因(不是所有红灯都该回 L5)

任一红灯 → **先归因,再决定**。归因只有一种做法,不接受口头判断:

```bash
git stash push -u -- weiran-common weiran-system weiran-app web openspec   # 把本次改动整体移走
<那条红掉的命令>                          # 在基线上重跑
git stash pop
```

| 基线上的结果 | 判定 | 去向 |
|---|---|---|
| 基线**绿** | 本次引入的回归 | **回 L5**,不得继续 |
| 基线**同样红** | 存量红灯,与本次无因果关系 | 允许放行,但**必须**:① 把基线对比的证据写进本节;② 登记到 `openspec/state/waitlist.md`(带症状);③ 在「结论」里把该项标成带条件放行,交 L9 人闸确认 |

**为什么不能只写「这条跟我没关系」**:存量红灯会让「三绿」这个硬闸门恒假,执行者要么卡在一个
自己修不了的闸门前,要么开始习惯性地为红灯找理由 —— 后者一旦成为习惯,真正的回归也会被一起放过。
把「必须跑一次基线」写成动作,是让这句话有成本、因而不能随口说。

**不稳定(flaky)的红灯同样按此归因**:失败集合每次不同 ≠ 与本次无关,基线上重跑几次才算数。

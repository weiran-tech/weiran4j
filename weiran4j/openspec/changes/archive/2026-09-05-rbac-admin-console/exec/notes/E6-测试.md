## 为什么这么做

这个单元的主要价值不是"写了多少测试"，而是**测试过程中发现并修复了 5 个此前未暴露的真实缺陷**：

1. **H2 保留字语法错误**：`pam_ban.value` 列名未加引号，H2（`MODE=MySQL` 模式下）仍将 `VALUE` 作为保留关键字，`CREATE TABLE` 语句直接语法错误，容器根本起不来。这是我自己新增 schema.sql 表定义时的疏漏（`pam_permission.group` 已有先例加了引号，但没意识到 `value` 也是保留字）。
2. **MyBatis-Plus 生成 SQL 未转义保留字列名**：即使 schema.sql 定义时加了引号，`PamBanDO.value`/`PamPermissionDO.group` 两个 DO 字段本身没有 `@TableField` 转义声明，MyBatis-Plus 自动生成的 INSERT/UPDATE/SELECT 语句里这两列仍是裸写，在 H2 上直接语法错误。生产 MySQL 环境虽然不会报语法错误（MySQL 不保留这两个词），但这是一个此前完全没被验证过的隐患——如果不是这次集成测试，这个问题要等到有人真的用 H2 或换到别的更严格 SQL 方言时才会暴露。
3. **`pam_ban.note` NOT NULL 违反**：`MyBatisBanRepository.insert`/`update` 直接把 `Ban.note`（可空）传给 MyBatis-Plus 的 `set()`，前端表单不填备注时传 `null`，触发 `NULL not allowed for column "note"`。这是照抄 `Account`/`disableReason` 处理模式时漏做的一步——`Account` 那边所有可能为 null 的字符串字段在 `toDO`/`update` 时都统一走了 `orEmpty()`，`Ban` 的实现漏了这一处。
4. **测试代码自身的密码不一致 bug**：`RbacAdminEndpointIT.accountManagementFullCycle` 新增账号用密码 `"newone-123456"`，但 `login()` helper 固定用 `RAW_PASSWORD = "weiran-123456"`，导致"新账号能否登录"这个断言从一开始就注定失败——不是被测代码的问题，是我写测试时的疏忽。
5. **jsdom 缺少 Canvas 2D 支持导致 Semi 组件测试崩溃**：`Avatar` 组件依赖的 `lottie-web` 在模块加载阶段就尝试获取 canvas context 并立即写 `fillStyle`，jsdom 默认 `getContext()` 返回 `null` 导致 `TypeError` 崩溃整个测试文件。这不是本项目代码的 bug，是 Semi Design 在 jsdom 测试环境下的已知兼容性问题，通过在 `test-setup.ts` 里给 `getContext` 打一个返回 Proxy 假对象的 stub 解决，没有引入 `jest-canvas-mock` 这类专门依赖。

其中 bug 1-3 如果不是走了完整的端到端集成测试（而只做 mock 化的单元测试），几乎不可能被发现——这印证了 exec/plan.md 里"应用服务用例编排不做隔离单测、改由集成测试覆盖"这个决定是对的：mock 掉 Repository 的单测测不出真实的 SQL 保留字冲突和 NOT NULL 约束违反。

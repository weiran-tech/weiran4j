## D-002 底座依赖方式（2026-09-03）【已取代 → D-008】

以 **Maven 依赖 + BOM** 方式消费公司底座 [wuli3-gradle](https://github.com/Y-cs/wuli3-gradle)，
不做 git submodule、不 vendor 源码。

- 理由：仓库解耦、构建轻、底座升级只改版本号。
- 代价：底座未发布到公共仓库时需先 `./gradlew publishToMavenLocal` 本地调试。
- build-logic 约定插件无法跨仓复用，weiran4j 自建一份 `build-logic`，照搬底座的质量规则
  （JDK 21 toolchain、Checkstyle、Error Prone + NullAway、禁 `java.util.Date`、JSpecify 空安全）。

## D-006 关闭 Gradle 配置缓存（2026-09-04）

Spotless 的 palantir-java-format 步骤与 Gradle 配置缓存不兼容：配置缓存恢复的类加载器
拿不到 `--add-exports` 的模块开放，palantir 在 `JavaInput.<clinit>` 抛
`IllegalAccessError`（访问 `com.sun.tools.javac.util.Log`），被 Spotless 包成
`palantir-java-format(InvocationTargetException)` 报为 lint 错误。

**定位过程**（记下来是因为症状极具误导性）：

1. 失败文件集合每次都变（实测 3 → 1 → 2），一度以为是构建缓存坏了；
   实际是已通过的文件 UP-TO-DATE 不再重跑，所以只剩「尚未成功过」的文件在报错。
2. 排除了：`clean` 与并行任务竞争、daemon 复用、构建缓存、文件内容（逐字节对比过
   通过与失败的两个同形状 `package-info.java`，完全一致）。
3. 用 palantir 的 jar 单独跑那个文件，才拿到被 Spotless 吞掉的真实异常。
4. 对照实验：`--no-configuration-cache --rerun-tasks` 连跑 3 次全绿。

**决定**：关闭配置缓存。代价是冷构建配置阶段慢几秒；收益是门禁不再随机变红。
不可信的门禁比没有门禁更糟——它会训练人忽略红灯。

已登记为 `openspec/state/waitlist.md` 的 T-001，Spotless 修复后可重新打开。

## D-007 前端不照搬 mono4ts 的 vite 配置（2026-09-04）

mono4ts 的 `vite.config.ts` 有大段 semi-ui / rolldown 分包调优，那是它在自己的首屏
体积问题上一次次踩出来的结论，不是通用最佳实践。weiran4j 当前没有体积问题，
照抄只会先背上一份看不懂的复杂度。等体积真的成为问题，再回去取那份经验。

依赖也只取了必要子集（React + Router + TanStack Query + Semi UI + zod），
没有搬 PDF、Excel、Monaco、图表、流程图等重型库——它们属于具体业务，用到再加。

## D-008 框架重写：去 wuli3、不兼容 PHP、对标 mono4ts 后台底座（2026-09-26）

仿照 `/Users/duoli/Projects/hanrui-jinnuo/mono4ts`（Hono + Drizzle + Semi 的后台）的能力形态，
把 weiran4j 重写为 **Java 21 + MySQL 8 + Semi UI** 的后台管理框架底座。原地重写，旧实现可从 git 历史回溯。

决定（经用户确认）：

1. **能力范围 = 标准后台底座**：登录/JWT、用户、角色、菜单（动态路由 + 按钮权限）、部门、字典、系统配置、
   登录日志、操作日志；前端 AdminLayout（侧边菜单、多页签）。mono4ts 的业务台账 / 工作流 / 报表不在范围内。
2. **保留 DDD 五层**：`weiran-system`（身份与权限）与 `weiran-platform`（字典 / 配置 / 操作日志）各五层。
3. **去掉 wuli3 底座**：直接基于 Spring Boot 3.5 + MyBatis-Plus + Flyway；新增 `weiran-framework`
   承担统一响应、全局异常、认证拦截、权限注解、操作日志切面等原先由 wuli3 提供的职责。
   理由：wuli3 未发布到任何远程仓库，新 clone 无法构建（原 T-002），且其字符串 `code` 与前端生态不一致。
4. **不兼容 PHP weiran-v1**：不再读写 `pam_*` 表、删除历史密码算法与 Ban 功能、`/api/v1` 前缀改为 `/api`。
   原宪法 CP-7 / CP-8（迁移期约束）改写为 Flyway 迁移不可变 / BCrypt + token_version。

契约文档：[`01-架构与接口契约.md`](01-架构与接口契约.md)。
代价：旧的 4 份 openspec 主 spec 全部标为 `superseded`；`docs/10-模块映射.md`、`docs/20-数据迁移注意事项.md` 删除。

# 数据迁移注意事项

> weiran4j 与 weiran-v1 在迁移期**并行读写同一套 `pam_*` 表**。
> 本文记录已经确认的坑，每条都带「不处理会怎样」。

## 1. `pam_account.password` 列宽必须放宽（阻塞项）

PHP 侧建表是 `varchar(45)`，够存历史算法的 32 位 md5 哈希。
**BCrypt 哈希固定 60 字符**，写进 45 列会被 MySQL 静默截断（非严格模式下）。

```sql
ALTER TABLE pam_account MODIFY COLUMN password VARCHAR(72) NOT NULL DEFAULT '';
```

**不处理的后果**：用户改密或历史密码懒迁移时，写入的哈希被截成 45 字符，
此后 BCrypt 校验永远不通过——表现为「改密提示成功，但从此登不进去」，且没有任何报错。

> 72 而不是 60：BCrypt 的 `$2b$` 变体与未来可能的算法标识留余量。

## 2. 两套密码算法并存


|              | 算法                                        | 长度               | 用途               |
| -------------- | --------------------------------------------- | -------------------- | -------------------- |
| 历史（PHP）  | `md5(sha1(明文 + 注册时间) + password_key)` | 32 位十六进制      | **仅校验**存量账号 |
| 当前（Java） | BCrypt，工作因子 10                         | 60 字符，`$2` 开头 | 新账号与迁移后账号 |

识别靠前缀，不需要额外的版本列：BCrypt 以 `$2` 开头，历史哈希是纯十六进制。

**懒迁移**：历史哈希校验通过的那一刻立即用 BCrypt 重哈希并落库
（`AuthApplicationService#verifyPassword`）。为什么不批量迁移：批处理拿不到明文密码，
历史哈希只能在用户成功登录时才有条件重算。

**这意味着**：只要还有存量用户没登录过，历史算法就不能删。什么时候能删，
取决于「多久没登录的账号可以要求重置密码」这个业务决定，不是技术决定。

### 注册时间的格式是硬约束

历史算法把注册时间**作为字符串**参与摘要，格式必须是 Laravel `Carbon::toDateTimeString()`
的 `uuuu-MM-dd HH:mm:ss`。两个已经踩过的坑：

- 用 `LocalDateTime.toString()` 会得到 ISO 的 `2019-05-01T08:30`（T 分隔、秒省略），
  摘要完全不同 → **全部存量账号密码校验失败**。
- `DateTimeFormatter.ofPattern(pattern)` 不传 Locale 会跟随 JVM 默认，
  部署到 `th-TH` 之类使用佛历的机器上年份会变 → **同样是全部存量账号集体失败**，
  且只在特定机器上复现。必须显式传 `Locale.ROOT`。

## 3. 令牌不通用，迁移需要重新登录一次

PHP 用 `tymon/jwt-auth`，自定义 claim 是 `user: {type, salt}`，
其中 `salt = md5(sha1(password_key) . password)`。

weiran4j 的 claim 是 `sub` / `typ` / `stp`，`stp` 是 `SHA-256(密码哈希 | 盐值)` 的前 16 位十六进制。

两者签名密钥与载荷结构都不同，**互不通用**。切流时用户需要重新登录一次。
这是有意的取舍：兼容 PHP 的令牌意味着要把已破的 md5 摘要继续带进新系统。

## 4. 统一响应格式不同


|                        | 成功判据                     | 结构                                          |
| ------------------------ | ------------------------------ | ----------------------------------------------- |
| PHP (`Resp`)           | `status === 0`（数字）       | `{status, message, data}`                     |
| weiran4j（wuli3 底座） | `code === '0'`（**字符串**） | `{code, message, timestamp, requestId, data}` |

失败时 PHP 返回 `status` 为 1/2/5/7 等小整数；weiran4j 返回结构化错误码字符串，
形如 `WEIRAN.SYSTEM.BAD_CREDENTIALS`（`<服务>.<模块>.<错误名>`，
服务段取自 `application.service.service-code`）。

**前端切流时必须同时改判据**，逐接口灰度会出现两种格式并存，需要在请求层按接口路径分流。

## 5. HTTP 状态码语义

底座默认按错误归属映射（CALLER → 400，SERVER → 500）。weiran4j 覆盖了认证类错误：


| 场景                         | 状态码 | 错误码                                                |
| ------------------------------ | -------- | ------------------------------------------------------- |
| 密码错 / 账号不存在          | 401    | `BAD_CREDENTIALS`（**两者返回完全相同**，防账号枚举） |
| 令牌无效 / 过期 / 因改密失效 | 401    | `TOKEN_INVALID` / `TOKEN_EXPIRED` / `TOKEN_STALE`     |
| 账号禁用 / 封禁              | 403    | `ACCOUNT_DISABLED` / `ACCOUNT_BANNED`                 |
| 缺少权限                     | 403    | `PERMISSION_DENIED`                                   |
| 入参校验失败                 | 400    | 底座默认                                              |

## 6. 尚未迁移的表

`pam_token`（设备令牌台账）、`pam_ban`（封禁记录）、`pam_log`（登录日志）、`sys_config`
目前 weiran4j 没有读写。其中：

- **`pam_token` 影响单设备登录约束**：PHP 侧靠它实现「同类型设备只允许一个活跃令牌」。
  weiran4j 当前签发的 JWT 是无状态的，**不受该约束**——同一账号可以在多设备同时在线。
  如果这条业务规则要保留，需要把令牌台账一起迁过来，那会让令牌从无状态变成有状态，
  是一个需要单独立项的设计决定，不要顺手加。
- `pam_log` 缺失意味着**登录审计在 Java 侧是断的**，只有 `pam_account.login_times`
  与 `logined_at` 被更新。底座有 `wuli3-audit-log-spring-boot-starter`，接它比照搬 PHP 表更合适。

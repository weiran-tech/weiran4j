## 模块机制的对应关系

PHP 侧的模块靠 `ServiceProvider` + `manifest.json` 注册：合并配置、注册路由、声明权限点。
Java 侧的等价机制是 **Spring Boot 自动配置**：

| PHP 机制 | Java 对应 |
| --- | --- |
| `ServiceProvider::register()` | `@AutoConfiguration` 类 + `META-INF/spring/...AutoConfiguration.imports` |
| 路由文件 `Http/Routes/*.php` | `@RestController` + 适配层 `@Import` 显式登记 |
| `manifest.json` 的权限声明 | 待定：建议各模块提供 `PermissionContributor` Bean，启动时汇总入库 |
| 配置合并 | `@ConfigurationProperties` + `@EnableConfigurationProperties` |

## 新增一个模块的步骤

以新增 `weiran-area` 为例：

1. 建目录 `weiran-area/weiran-area-{api,domain,application,infrastructure,adapter}`
2. 每层写 `build.gradle.kts`，照抄 `weiran-system` 对应层的插件与依赖形状
3. 在根 `settings.gradle.kts` 的 `include(...)` 追加五个扁平模块名，
   并在下方 `listOf(...).forEach` 里追加目录映射
4. 在 `weiran-dependencies` 的 constraints 里追加五个模块坐标
5. infrastructure 与 adapter 各写一个 `@AutoConfiguration` 并登记进 `.imports` 文件
6. `weiran-app/build.gradle.kts` 追加对 adapter 与 infrastructure 的依赖

> 第 3、4 步动的是全仓单点（`settings.gradle.kts` 与 BOM），按宪法 CP-4 与
> openspec 的分层要求，必须排进串行的 Layer 0，两个并行执行单元同时改必冲突。

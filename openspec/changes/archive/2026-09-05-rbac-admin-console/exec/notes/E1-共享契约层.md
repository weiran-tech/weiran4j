## 为什么这么做

- 关键决策：所有 record 均照抄现有 `LoginCommand`/`LoginResult`/`CurrentAccountView` 的写法——紧凑构造器里对非空字段做 `Objects.requireNonNull`，可空字段用 `@Nullable` 标注且不做校验。三个 Service 接口只依赖 `weiran-common` 的 `PageQuery`/`PageResult`，不引入新的分页类型。
- 考虑过但放弃的方案：`LoginLogView` 本可以设计成单条非分页返回（因为底层只有 `pam_account.logined_at`/`login_ip` 一个快照字段，"分页"语义天然退化为 0-1 条），但 design.md 的 API Design 表已明确写 `PageResult<LoginLogView>`，为保持契约一致性未改动返回类型，只在 `PamService.loginLogs` 的 javadoc 里注明这个事实（返回 `PageResult` 只是为了与其它列表接口保持统一响应形状）。

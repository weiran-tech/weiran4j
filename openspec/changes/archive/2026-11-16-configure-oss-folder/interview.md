# Interview

## 一句话需求

- 用户："oss 存储目录 增加一个默认文件夹名称"
- 补充："当前默认是 media"

## 澄清记录

| # | 提问 | 回答 | 由此确定的决策 |
|---|---|---|---|
| 1 | 默认文件夹是否新增 weiran 等根目录 | 当前默认是 media | 保留 media 默认值，将 OSS 根文件夹提取为部署配置，不叠加另一层根目录 |

## 边界

### 要做

- 为 OSS 媒体上传添加文件夹配置，默认 media；直传授权与后端代传共用该值。
- 校验文件夹名，保持票据用户与目录绑定；旧对象 URL 和删除能力保持兼容。
- 同步配置示例、部署文档、契约与状态说明，并覆盖配置及路径安全回归。

### 明确不做

- 不迁移或重命名 Bucket 内已有对象，不修改数据库表结构。
- 不新增后台配置页面，不修改本地存储与批处理存储的目录行为。
- 不新增未登录上传入口，不改权限与上传格式大小限制。

### 本次不决定(留给后续 change)

- 多级根目录、私有读链接与历史对象批量迁移。

## 验收标准

- [ ] AC-1 未配置文件夹时，OSS 对象名仍为 media/u/<用户标识>/<UTC日期>/<UUID>.<扩展名>。
- [ ] AC-2 配置文件夹 assets 后，直传策略、票据和后端代传对象名使用 assets/u/...。
- [ ] AC-3 空值、斜杠、路径穿越及不安全字符导致配置失败，不生成越界授权。
- [ ] AC-4 旧 media 对象与已登记的历史自定义文件夹对象可安全删除；目录外和路径穿越对象被拒绝，原 URL 不重写。
- [ ] AC-5 示例与部署说明包含变量名和默认值，相关测试和质量门禁通过。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 配置归属 | OSS 部署配置 | 数据库与前端表单 | 属于 Bucket 组织配置，不引入运行期全局配置切换 |
| 根路径 | 单级文件夹，默认 media | media 前再增加目录 | 保持默认部署与现有 URL 兼容 |
| 历史对象 | 保留对象名和 URL | 批量移动 | 避免破坏已有链接和引用 |

## 未决歧义

- 无

## 对下游的硬约束

- 不暴露 OSS 凭据；不放宽直传用户、票据签名、有效期或对象结构校验。
- 本次配置只影响 OSS 新媒体对象；本地与批处理路径保持原行为。

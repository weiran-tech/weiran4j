# Proposal

## Why

API 测试框架已经可用，但外部流程只检查存活和认证，无法发现部署环境中的 CRUD、分页、树、授权变化与清理问题。用户要求「写 api 的测试」；首批把核心后台路径变成可发现、可验证、可恢复的 HTTP 工作流，真实执行结论与合成验证分开。

## What Changes

- 新增核心读契约、五类资源生命周期、权限边界和地区只读共 8 条 API 流程。
- 扩充匿名 API 拒绝矩阵，复用 Cookie/CSRF 请求、严格证据、参数与注册框架。
- 建立独立 API 会话 fixture、限定所有权的资源清理/恢复；写入必须显式允许。
- 增加离线负例和独立合成 HTTP 装配，更新 docs 测试入口与覆盖边界。
- 保留已有 Java 集成测试及全部现行门禁，不复制生产规则作为替代实现。

## Scope

### In Scope

与 interview 的要做一致：核心业务外部 API 工作流、专属数据与恢复、相应框架装配回归和文档。仅 tests/、必要根测试脚本、docs/现状及本 change。

### Out of Scope

- 不改 Controller/DTO/数据库、种子、生产认证策略；不操作既有用户/角色/菜单/字典/配置，不修改操作者密码或权限。
- 不读取源项目凭据、不默认使用 admin123、不自动启动真实业务服务、不把模拟结果报告为真实通过。
- 不新增业务权限码或菜单种子；临时菜单与角色仅在显式允许写入的测试环境通过现有 API 创建，不成为发布资源。
- 不新增前端页面、组件、E2E 或 Bruno 重复集合，不扩大为性能、压力或破坏性安全测试。

## Dependencies

- 产品/设计：本设计 L3 审阅后实施。
- 后端/数据库：无修改，无 Flyway；真实执行需已运行的本项目独立测试环境。
- 前端：无依赖；不需要后台 UI 或 Chromium 才能运行新增 API 流程。
- 运维/配置：专用密码测试账号；写入额外显式 ALLOW_WRITE=true；敏感值不入版本库。
- 测试：复用现有根 Playwright/Node/TS，无新依赖；doc、旧离线/浏览器与 L7 门禁保留。

## Risks

| 风险 | 触发场景 | 应对方案 |
|---|---|---|
| 污染数据 | 中断或清理失败 | 写前持久化清单、精确所有权、逆序清理和专门恢复入口 |
| 敏感信息泄漏 | 请求断言打印响应 | 固定错误、白名单证据、禁自动追踪；哨兵回归 |
| 虚假覆盖 | 仅有 mock 成功 | 合成与真实分栏；真实环境不足明确未运行 |
| 版本/权限变化 | 使用陈旧草稿或授权缓存 | 读后带版本、验证冲突状态保留、同一用户会话检查撤权 |

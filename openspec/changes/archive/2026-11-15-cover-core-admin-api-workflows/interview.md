## 边界

### 要做

- 新增 8 条 API 流程：core-read、user-lifecycle、role-lifecycle、menu-lifecycle、dict-lifecycle、config-lifecycle、permission-boundary、region-read；扩充已有 access-boundary 的匿名检查。
- 断言数字 code、HTTP 状态、分页 total/list、树/详情形状、参数错误、冲突与实际状态变化。
- 用户/角色/菜单/字典/配置仅操作本次唯一前缀创建的数据；受限账号由测试自行创建，在自己的角色上授予/撤回已有权限，验证允许/403及授权快照更新。
- 独立 Cookie/CSRF API fixture；私有资源清理清单与失败恢复；清理结果必须通过后置读取核验。
- 写操作显式 opt-in；恢复限定本环境、本次清单与创建的数据，避免误删既有数据。
- 离线步骤故障回归、隔离合成 HTTP 装配，以及 docs 的覆盖与运行说明；原测试继续保留。

### 明确不做

- 不改 Controller/DTO/数据库、种子、生产认证策略；不操作既有用户/角色/菜单/字典/配置，不修改操作者密码或权限。
- 不读取源项目凭据、不默认使用 admin123、不自动启动真实业务服务、不把模拟结果报告为真实通过。
- 不新增业务权限码或菜单种子；临时菜单与角色仅在显式允许写入的测试环境通过现有 API 创建，不成为发布资源。
- 不新增前端页面、组件、E2E 或 Bruno 重复集合，不扩大为性能、压力或破坏性安全测试。

### 本次不决定(留给后续 change)

- 文件/媒体/批处理、短信/MFA/SSO、地区写入与导出、用户外部身份绑定、完整配置类型矩阵、任意角色全量组合。
- 专用真实账号的值、真实 CI 凭据托管与执行调度；这些不是写进版本库的设计输入。

## 验收标准

- [ ] AC-1 新增 8 条 API 流程均完成声明、工具发现、共享步骤索引；缺前提失败，不 skip 或假通过。
- [ ] AC-2 核心读取覆盖用户/角色/菜单/字典/配置/两种日志，地区覆盖公开和后台读取，断言实际 schema 与分页/树约束，允许合法空数据。
- [ ] AC-3 五类生命周期验证创建、读取、更新、删除和相应业务约束；临时账号/角色验证允许、拒绝、撤权后的真实请求结果。
- [ ] AC-4 没有 ALLOW_WRITE=true 时生命周期/权限流程在任何登录或业务写入前拒绝；唯一前缀资源逆序清理，失败有私有恢复清单，不碰既有记录。
- [ ] AC-5 Cookie/CSRF、版本冲突、失败清理与隐私有离线负例；各新增流程在隔离合成 HTTP 服务上实际执行，合成与真实结果分开。
- [ ] AC-6 原有离线/浏览器回归、项目 build/test/lint、文档构建与 OpenSpec 门禁通过；docs 更新运行步骤、覆盖和限制。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 作用层级 | 外部 HTTP 工作流 | 复制已有 JUnit 断言 | 使刚迁入的 tests/ 能验证部署中的真实接口。 |
| 数据 | 测试自建、唯一标记、finally与可恢复清单 | 修改种子或现有业务数据 | 独立执行、失败可清理，结果可重复。 |
| 权限 | 临时用户和角色，引用已有权限定义 | 修改管理员/现有角色 | 不污染既有账号权限。 |
| 验证 | 离线/合成独立，真实执行按输入明确报告 | 缺真实条件仍声称通过 | 保证报告可信。 |

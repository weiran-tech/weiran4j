# Proposal

## Why

- 需求来源：interview.md，用户选择审查建议 1、3、4。
- 菜单单次请求的合法性不能阻止并发互挂或父删子增，且菜单编辑尚无旧草稿保护。
- 跨实例权限缓存有 30 秒旧授权窗口，其他管理员变更又无法使已打开页面的无限期缓存刷新。
- OpenAPI 只看到声明返回类型，实际包络由运行时添加，客户端生成会获得不完整 schema。
- 目标：使菜单不变量在并发下成立，使授权变化有明确生效边界，使公开契约描述真实响应。

## What Changes

- 新增：菜单数据库结构守卫、授权共享修订号、单次身份及菜单快照查询、真实 HTTP/schema 一致性验证。
- 改造：菜单版本冲突、授权缓存校准、前端可见时轮询/恢复刷新/403 恢复、自动 OpenAPI 包络及失败 schema。
- 复用：Hierarchy、现有编辑冲突 hook/组件、Caffeine、统一响应策略、docs React 挂载方式。
- 下线/不做：前端身份与菜单无限期独立快照；不引入 Redis，不替换认证 SPI。

## Scope

### In Scope

- sys_menu.md#06、artifact.md#02/#26/#04 的行为及现状记录。
- 对应后端、前端回归，docs 中可操作的本地演示及部署约束。

### Out of Scope

- 短信/MFA/手机号绑定挑战共享存储。
- 日志查询优化、依赖分层专项治理、分支保护设置。
- 全平台请求幂等、其他资源全面版本化、引入 Redis 或消息总线。
- 全量生成并替换前端 API 客户端。

## Dependencies

- 产品/设计：本 change 的 L3 审阅。
- 后端：现有 MySQL、事务、统一响应与 springdoc，新增的文档支持为可选装配。
- 前端：TanStack Query、共享冲突反馈与权限上下文。
- 数据库：只追加 V202611142100__system_menu_and_authorization_boundaries.sql。
- 运维：维护窗口同步切换新旧实例和前端，不增加外部服务。
- 测试：JDK 21、Docker/Testcontainers、docs 构建与浏览器演示。

## Risks

| 风险 | 触发场景 | 应对方案 |
|---|---|---|
| 全局修订号争用 | 授权写高频 | 授权写本就低频，短事务、不包外部调用，监控等待 |
| 前端校准失败 | 网络不可用 | 保留旧快照并持续提示；后端每请求仍拒绝已撤权限 |
| OpenAPI 二次包装 | 显式 ApiResponse / Skip 注解 | 共享判定与端到端 schema 对照测试 |
| 混合旧实例 | 旧写不推进修订号 | 维护窗口切换，回退时限制相关写入并优先前滚 |

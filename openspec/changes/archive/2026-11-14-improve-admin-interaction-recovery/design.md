## Architecture

- 共享的小型列表反馈组件展示错误与空态；页面仍负责查询、筛选和表格数据。
- 共享的表单关闭保护 hook 读取当前值及初始值，控制关闭确认；保存成功直接执行页面原关闭回调。
- 地区页面独立管理筛选结果的默认展开与后续手动展开选择，不影响导出和查询接口。

## Data Flow

1. 查询开始维持现有 loading；首次失败显示持久错误和重试，有缓存的刷新失败保留原表格并显示更新失败。
2. 成功无记录按是否存在已生效筛选显示“暂无记录”或“没有匹配结果”；后者提供清空条件，成功后不残留错误。
3. 用户请求关闭表单：保存中拒绝关闭；无实际变化直接关闭；有变化弹出“放弃修改？”确认，默认聚焦安全选项“继续编辑”。
4. 保存校验失败不关闭；请求失败保留输入；请求成功不经过放弃确认，正常退出。
5. 地区筛选条件变化后以新结果初始化展开路径；之后手动折叠优先，同条件刷新不覆盖。清空所有条件恢复折叠。

## 跨模块契约变更(DS-1)

无框架或模块间契约变更。可复用封装仅属于 manage，待实现后登记到 components.biz.md。

## API Design(DS-2)

不新增或修改 API。重试复用现有 refetch，保持当前已生效条件和分页。统一响应成功码仍为数字 0。

## Database Design(DS-3)

无数据库变更，无 Flyway 脚本；不修改原有未提交批处理迁移。

## 权限与已知缺口(DS-4)

- 保留现有 Permission 和行操作权限判断，错误反馈不引入额外写权限。
- 无新写接口，无新增审计点。
- 本轮不处理其他页面、地区父级选项数据源、URL 查询恢复及操作列宽。

## 分层与装配(DS-5)

无后端分层或装配变化。前端组件不直接发请求，由页面传入重试与清空回调；关闭保护不持有业务请求。

## 前端设计(DS-6)

### 列表反馈

| 状态 | 展示 | 可执行操作 |
|---|---|---|
| 首次加载中 | 沿用表格 loading | 等待 |
| 首次加载失败 | 持久错误提示，不显示成功空态 | 重试当前查询 |
| 有缓存时刷新失败 | 原数据与“更新失败”提示并存 | 重试当前查询 |
| 成功且无条件、无记录 | 暂无记录 | 保留有权限的新增入口 |
| 成功且有条件、无结果 | 没有匹配结果 | 清空条件 |

- 重试进行中显示 loading 并避免重复点击；错误提示本身不再次触发 Toast。
- 使用明确的文本与可聚焦按钮，错误区域可被辅助技术识别。

### 表单输入保护

- 只对比当前实际字段内容与初始内容，忽略字段注册导致的无意义空值差异，不依赖 touched 状态。
- 修改后恢复初值可直接关闭；数组等复合字段按内容比较，不因新引用误判。
- 取消按钮、关闭按钮和 Esc 共用同一关闭判断；确认框取消返回原表单且保留内容。
- 保存中禁用取消、关闭、Esc 和重复提交；请求失败后恢复这些交互。
- 保护对象是两个新增/编辑弹窗的关闭操作；本轮不引入全局路由拦截或浏览器刷新草稿恢复。

### 地区筛选展开

- 非空已生效关键词、级别或状态条件的结果返回后，展开返回树的必要路径，命中后代直接可见。
- 去掉一个条件且仍有其他条件时，按新结果重新初始化；全部条件清空后折叠。
- 用户手动收起或全部收起后，刷新同条件保留其选择；异步旧查询结果不能覆盖新条件的展开状态。

## Observability

- 沿用统一请求层的 requestId 与错误 Toast，不增加表单值或密码日志。
- 列表错误在页面内持续可见，可通过重试恢复。

## Test Plan

| 层级 | 范围 | 验证方式 |
|---|---|---|
| 交互回归 | 首次失败、刷新失败、重试成功、两种成功空态 | 用户与地区列表组件测试，对应 AC-1/AC-2 |
| 表单交互 | 无改动关闭、修改后继续/放弃、改回初值、延迟保存成功/失败 | 真实 Semi Form 渲染，对应 AC-3/AC-4 |
| 地区树交互 | 三级命中路径、手动折叠、同条件刷新、条件清空与切换 | RegionsPage 测试，对应 AC-5 |
| 门禁 | 现有质量与规格规则 | 使用 project.json 的 commands 记录真实证据，对应 AC-6 |
| 浏览器 | 用户/地区弹窗确认焦点、错误反馈布局和三级结果可见性 | 真实页面验证；如环境阻塞则如实记录 |

## Rollout / Rollback

- 随前端常规版本发布，无后端或数据迁移依赖。

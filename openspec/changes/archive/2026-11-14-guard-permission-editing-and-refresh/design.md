## Architecture

- Query hooks 负责请求与失效，页面负责草稿和交互；状态视图只接收数据、加载/失败状态与回调。
- 权限可编辑判定供按钮、选项和保存处理器共用，避免 UI 禁用与实际提交前置不一致。
- docs 通过现有 ClientOnly 与 Vue/React 挂载方式复用实际状态视图或同一判定逻辑；示例的状态驱动与数据完全在本地。

## Data Flow

1. 权限抽屉并行读取菜单树和角色详情，两者成功且没有读取/失败状态后开放编辑与保存。
2. 任一失败进入可重试状态；有旧数据时可以展示供参考，但禁止依赖旧状态进行编辑和保存；重试保留用户已经做出的草稿选择。
3. 设置页按各必要查询分别提供错误恢复，读取中与失败不混用；重试使用 refetch，不重载页面或重置本地草稿。
4. 角色写入成功后，保留角色资源缓存失效，并使当前资料和菜单前缀失效，活动查询重取后由既有 Permission 和导航渲染新结果。
5. docs 场景控制器驱动加载、失败、成功和权限快照更新，复用相同的视图与行为条件，不调用业务接口。

## 跨模块契约变更(DS-1)

无后端契约变更。前端状态视图允许 docs 通过内部源码路径复用，业务实现不依赖 docs；不把业务页面加入公共发布包。

## API Design(DS-2)

无新增或修改 API，继续使用菜单树、角色详情/写入、安全设置、上传规则和配置列表的现有接口。响应成功码为数字 0；重试与刷新沿用原请求层。

## Database Design(DS-3)

无表、索引、种子或迁移变化，既有未提交批处理迁移原样保留。

## 权限与已知缺口(DS-4)

- 不改权限码和后端权限校验；前端的失败状态保护用于防止意外提交。
- 两个依赖成功后的真实空权限仍允许明确保存，不把清空这个合法操作禁掉。
- 权限同步只覆盖当前会话发起的角色创建/编辑、删除与分配菜单；不加入跨实例、跨标签页或其他管理员会话的实时推送。
- 本轮不处理上传配置逐项保存的部分成功问题，保留 sys_config.md#05 待办。

## 分层与装配(DS-5)

无后端装配变化。前端仅在角色 Query hooks 的成功回调中组织身份缓存刷新；读取状态与页面展示保留各自责任边界。

## 前端设计(DS-6)

### 权限分配

| 状态 | 展示与动作 |
|---|---|
| 任一数据读取中 | 加载提示，保存/全选/清空/勾选不可操作 |
| 任一读取失败 | 持续错误和重试，禁止依赖不可靠数据的编辑与保存 |
| 两个读取成功 | 显示真实勾选，允许编辑；成功空值不算错误 |
| 重试成功 | 恢复已有权限，保留仍有效的用户草稿 |

保存处理器必须再次核实可用状态，不能仅依赖按钮 disabled。

### 设置恢复

- 安全设置明确区分首次加载与首次失败；成功后展示真实设置；后台刷新失败保留数据并禁用依赖该数据的修改/保存。
- 上传设置分别处理上传规则与配置列表的加载、错误和重试；有草稿时重试不覆盖输入，任何必要查询未成功或仍在刷新时禁用保存。
- 复用 ListFeedback 的反馈模式，允许用适合设置页的措辞；重试期间避免重复点击。

### 当前会话权限同步

- 角色写入成功后失效 authKeys.me 和 authKeys.menus 前缀，匹配当前活动会话键；保留原有 roleKeys 失效。
- 沿用现有活动 Query 与界面订阅，不通过清空全部 QueryClient 或刷新整页恢复权限。
- 后续身份读取失败由既有身份加载失败界面提供重试，不伪造已同步成功；失去页面访问权时沿用现有路由兜底。

### docs 演示

- 在 docs 增加“页面状态演示”入口，与公共组件演示并列可发现。
- 场景包括权限分配、安全设置、上传设置、权限同步。读者可以选择加载、失败、成功，执行重试，观察保存是否可用；权限同步展示更新前后的菜单和按钮。
- 共用实际无请求视图与状态判定，通过本地回调模拟恢复；不替换全局 fetch、不创建真实角色、不改实际安全配置。
- React 挂载/卸载和 ClientOnly 沿用文档站现有方式；必要的源码别名仅服务内部视图解析，不增加第三方依赖。
- 本次同步这三项涉及的演示；历史演示的整体迁移不在本轮范围。

## Observability

- 沿用统一请求层错误提示与 requestId，页面增加持续可见的恢复入口。
- 不输出权限草稿或安全配置内容；文档数据为虚构数据，浏览器刷新可复原。

## Test Plan

| 范围 | 验证 |
|---|---|
| 权限依赖保护 | 分别失败、延迟返回、刷新失败、重试恢复、合法空权限保存；断言失败阶段无写请求 |
| 安全设置 | 首次失败、重试成功、后台失败时保留读取值且禁止保存 |
| 上传设置 | 两个必要查询分别失败、重试后恢复保存、草稿不丢失 |
| 身份同步 | 角色各成功 mutation 触发活动 me/menus 重新读取，失败不触发；按钮与菜单采用新授权 |
| docs | 文档构建通过，浏览器操作四个演示场景，确认没有业务 API 请求 |
| 门禁 | project.json 原 build/test/lint，加 pnpm build:docs 与 OpenSpec 校验 |

# Interview

## 一句话需求

> 已经发布 1.1.1 wuli3 , 接入基座吧

## 澄清记录

| # | 提问 | 回答 | 由此确定的决策 |
|---|---|---|---|
| 1 | 目标版本与来源 | 用户指定 Wuli3 1.1.1；本机源码位于 ../wuli3-gradle，gradle.properties 为 1.1.1 | 使用发布制品，不通过跨仓源码依赖接入 |
| 2 | 当前版本基线 | 本会话已将 Boot 调整为 3.5.15、MyBatis-Plus 为 3.5.16；Wuli3 源码 BOM 相同 | 保留该版本基线，统一框架版本来源 |
| 3 | 制品仓库 | 用户确认使用 GitHub Packages，发布仓库为 https://maven.pkg.github.com/weiran-tech/wuli3 | 限定 Wuli3 group 从 GitHub Packages 读取，凭据由外部提供 |

## 边界

### 要做

- 核对发布制品与 Wuli3 BOM，设计并实现框架基础设施接入。
- 保留 DDD 层次、现有接口与数据库行为，梳理重复的 JSON、上下文、响应、异常、审计与持久化能力。
- 更新 D-008 后续架构决策和现状契约，验证纯领域层不受 Spring 依赖污染。

### 明确不做

- 不修改历史 Flyway、不复制 Wuli3 的演示业务、不改前端业务。
- 不为了通过构建关闭版本漂移、静态检测或覆盖率门禁。
- 不自动启用 Redis、消息队列、搜索引擎或其他未部署中间件。

### 本次不决定(留给后续 change)

- 没有业务消费需求的远程事件、RPC 与分布式中间件扩展。

## 验收标准

- [ ] AC-1 构建从确认的制品仓库解析 Wuli3 正式版 1.1.1，不依赖同级源码仓库或 Maven Local。
- [ ] AC-2 现有 HTTP 成功 code 仍为数字 0，错误码、HTTP 状态及分页字段保持兼容。
- [ ] AC-3 Cookie、CSRF、token_version 吊销与权限校验集成测试通过，外部头不能伪造登录身份。
- [ ] AC-4 JDK 21 下 spotlessApply、check、框架版本和分层门禁通过；依赖接入不引入额外中间件启动要求。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 发布物 | 固定 1.1.1 | includeBuild 或 SNAPSHOT | 下游与 CI 可复现 |
| 契约兼容 | 核对并适配现有协议 | 直接叠加两个 Web 响应与异常处理器 | Wuli3 默认包装、身份头恢复与本项目契约有差异 |
| 当前工作区 | 保留本会话已有 Boot/MP 改动，作为接入基线 | 回退既有用户指令 | 两项改动已验证且与 Wuli3 版本一致 |

## 未决歧义

- 无

## 对下游的硬约束

- 保留六位数字错误码、HttpOnly Cookie、CSRF、token_version 和现有业务数据库。
- domain/api 保持纯 Java 契约，不传递 Spring/MyBatis 类型。
- 凭据仅从本地忽略配置、环境变量或 CI Secrets 注入，不写入文档或日志。

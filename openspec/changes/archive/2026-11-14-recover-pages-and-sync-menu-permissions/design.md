# Design

interview 明确修复三项，explore 已核对最新 main（8bb458a）。已有 KeepAliveOutlet 管理页面生命周期，根与内容区已有 Suspense；必须区分等待和加载拒绝，保留外壳，避免一个故障页清空全部缓存。

## Architecture

- 使用 React 原生错误边界构建无请求的恢复组件，页面与 docs 共用。页面级边界位于导航外壳内，覆盖每个实际页面；根部另提供基础兜底，处理外壳或固定页自身异常。
- 页面加载包装将“稳定的正常实例”和“主动重试的新加载实例”区分，继续通过现有注册表解析页面，不绕过菜单路由注册或访问权限。
- 用户查询仍由页面 state + 原有 Query hooks 管理；菜单写入仍由资源 hooks 组织缓存刷新。

## Data Flow

1. 解析到页面后进入 Suspense 等待；渲染/加载拒绝由对应页面边界捕获，展示持续恢复界面。
2. 用户重试时，只重建当前故障页；若涉及失败 lazy，丢弃该失败加载实例并重新调用原 loader。
3. 成功恢复内容，持续故障继续提供重试/返回首页/主动刷新；不自动整页刷新或无限循环。
4. 高级筛选和快捷输入读取同一 draft.keyword；搜索使用现有 toQuery、条件删除和重置逻辑。
5. 菜单写入成功后并行失效 menuKeys、authKeys.me、authKeys.menus；活动查询重取驱动权限和导航更新。

## 跨模块契约变更(DS-1)

无后端跨模块契约变更。前端注册表保留已有路径解析和正常 lazy 引用稳定性，增加仅用于页面恢复的失效/重建能力；注册表恢复接口先串行实现并测试，之后接入页面边界。状态组件与 docs 之间只传本地数据/回调，不依赖服务。

## API Design(DS-2)

沿用现有菜单写入、当前用户/菜单和用户列表接口；keyword 参数与数字 code=0 不变。不新增 nickname 参数，不新增接口，不改变请求/响应 DTO 或后端校验。

## Database Design(DS-3)

无表、字段、索引、种子、菜单或 Flyway 变更，原有批处理迁移不触碰。

## 权限与已知缺口(DS-4)

原权限码与后端鉴权不变。菜单保存/删除仅成功后主动刷新当前会话身份；失败不清会话或刷新全部缓存。无跨会话推送。失去当前页面权限后沿用现有路由兜底；身份刷新失败沿用既有身份错误恢复，不伪造授权成功。

页面错误边界不捕获普通事件处理/业务请求失败，那些仍由请求与 Query 层处理；本次不增加遥测平台或修改后端审计。

## 分层与装配(DS-5)

前端通用恢复组件负责呈现与用户动作，注册表负责 lazy 解析/恢复，路由负责页面接入，Query hooks 负责身份失效。无后端装配、模块依赖或自动配置变化。

## 前端设计(DS-6)

### 页面故障恢复

- 内容层为每个页面提供独立边界，适用于动态菜单页及个人中心等固定页面；缓存页与非缓存页均遵守现有生命周期。
- 出错时显示“页面加载失败”及说明，操作为“重试”“返回首页”，并提供用户主动“刷新页面”兜底；不直接显示原始异常 message、堆栈或请求内容。
- 重试渲染错误时重挂当前页；失败 lazy 时建立新的加载实例，保证 loader 有新调用。浏览器/部署持续资源故障可能无法由 JS import 恢复，主动刷新作为明确兜底，不承诺所有资源故障都能局部恢复。
- 页面切换可离开故障页；页签刷新可重建故障页；正常页缓存不因其他页失败丢失。关闭故障页签同样释放其实例。
- 根部基础边界覆盖登录与外壳自身异常，允许主动重试/刷新；根部异常时无法承诺保留已出错的外壳。
- 不改变不存在组件的占位处理，不把后端业务错误当渲染崩溃。

### 窄屏关键字搜索

- 在用户高级筛选面板首部增加“关键字（用户名 / 昵称 / 手机）”，绑定同一个 draft.keyword，方便限高面板首屏可见。
- 宽屏快捷框仍保留；任何一处编辑立即反映在另一处，点击搜索或回车提交，输入时不自动请求。
- 原有单字段精确查询保持独立；keyword 继续按既有模糊规则参与条件组合。
- 清空、单条件移除、页码回到1、已生效标签语义保持一致，不改列宽与公共断点。

### 菜单权限同步

- 新增/编辑和删除菜单成功后，同时刷新菜单资源和当前 me/menus 前缀；保留会话后缀匹配。
- 刷新并行发起，避免菜单与资料串行等待；失败回调不做身份失效。
- 回归覆盖菜单变更导致按钮隐藏与导航变化，保留既有角色同步逻辑。

### docs 演示

- 扩展已有页面状态演示入口，增加真实恢复边界的渲染错误/懒加载失败与重试演示。
- 使用实际 SearchToolbar/SearchField 或共用的关键字输入组件演示宽窄屏共享草稿、搜索、重置与条件删除；使用本地虚构用户，不发 API 请求。
- 权限同步演示补充菜单写入成功/失败来源，继续复用 Permission，不依赖登录。
- ClientOnly 桥接保持，动态加载与卸载清理；新增组件登记 components.biz.md。
- 同步 artifact.md#22、sys_user.md#11、sys_menu.md#02 现状；解决后整条移入 changelog。

## Observability

页面提供持续可见的故障恢复，不在 UI 或新增日志输出原始异常堆栈、凭据或请求参数。普通请求沿用 requestId/Toast。无新上报服务与配置。

## Test Plan

| 范围 | 验证 |
|---|---|
| 边界与加载 | 渲染抛错恢复；loader 首次拒绝后第二次成功；持续失败无自动循环；根部兜底 |
| 路由与保活 | 缓存/非缓存页面隔离；正常页状态保留；切页、页签刷新与返回首页 |
| 用户筛选 | 共享草稿、请求keyword、条件标签、移除/重置与回第一页；浏览器窄屏入口可用 |
| 菜单同步 | 三类 mutation 成功/失败下活动me/menus读取与实际权限/导航呈现 |
| docs | 构建、桌面/窄屏操作、故障重试，无业务请求 |
| 完整门禁 | project.json 原 build/test/lint，JDK21，先spotlessApply；OpenSpec校验 |

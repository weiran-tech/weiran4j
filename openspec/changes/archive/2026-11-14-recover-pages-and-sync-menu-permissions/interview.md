## 边界

### 要做

- 管理页面渲染或懒加载失败时显示恢复界面，导航外壳与其他页面继续可用；恢复动作包含页面重试和返回首页。
- 首次动态加载失败后提供真正重新尝试加载的路径，不能只重挂同一个失败的 React.lazy 实例；持久资源故障提供用户主动刷新入口，不自动循环重载。
- 用户列表高级筛选增加与快捷输入共用的 keyword，窄屏可搜昵称；搜索、重置和条件标签保持原语义。
- 菜单新增/编辑和删除成功后，保留原菜单刷新并同步刷新当前用户资料；失败不触发身份刷新。
- docs 演示、测试、组件登记和已知问题现状同步。

### 明确不做

- 不改后端、数据库、菜单种子、权限码、HTTP 契约或第三方依赖。
- 不扩展到其他列表失败态、表单草稿保护、上传原子保存和地区候选树问题。
- 不增加跨会话实时推送、全局日志上报服务、自动刷新循环。
- 不自动归档、commit、push；不触碰原有三处无关改动。

### 本次不决定(留给后续 change)

- 其他表单保护、其他列表错误恢复接入顺序。

## 验收标准

- [x] AC-1 管理内容页面渲染失败时持续展示恢复界面，导航外壳保留，可重试或返回首页。
- [x] AC-2 动态模块首次失败后重试确实重新调用 loader，成功后恢复；持续失败可主动刷新，不自动无限重试。
- [x] AC-3 页面切换、页签刷新和保活场景下错误隔离到对应页面，其他页面仍可用；未登录固定页也有基础错误兜底。
- [x] AC-4 用户列表窄屏可通过高级筛选按 keyword 查询昵称；与宽屏输入共享草稿、搜索、重置、条件删除及页码重置行为。
- [x] AC-5 菜单创建/编辑/删除成功重取活动当前用户与菜单，按钮和导航采用新结果；写入失败不主动刷新身份。
- [x] AC-6 docs 本地演示异常/重试、窄屏搜索和菜单同步，不依赖真实服务；构建及浏览器验证通过。
- [x] AC-7 完整门禁真实执行，保留已有无关改动；对应已知问题解决后移到 changelog。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 故障隔离 | 页面边界与根部基础兜底 | 只在根节点捕获 | 内容故障不应卸载后台导航 |
| 动态加载重试 | 重建失败 lazy 的加载实例 | 仅清除错误边界状态 | React.lazy 缓存失败，假重试无法恢复 |
| 查询入口 | 共用 draft.keyword | 新增独立 nickname 条件 | 已有后端 keyword 支持昵称，不改接口 |

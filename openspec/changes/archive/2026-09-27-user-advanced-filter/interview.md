## 一句话需求

> 用户原话,不要改写。

- 高级筛选是单字段查询, 需要补充后端接口

背景(同一会话上文):用户管理的搜索栏已按设计稿 `wuli-design/testing.pen`「用户列表」改造,高级筛选面板目前只放了
后端已支持的关键字 / 所属部门 / 状态三项;设计稿其余字段因后端 `UserQuery` 不支持而未放出,登记为
`openspec/state/bizs/sys_user.md#08`。

## 边界

### 要做

- 后端 `GET /api/users` 新增独立查询参数:用户名(精确)、用户 ID(精确)、手机号(精确)、邮箱(精确)、角色 ID(拥有该角色)、
  性别(等值)、创建时间范围(闭区间)、最后登录时间范围(闭区间)。所属部门 `departmentId`、状态 `status` 已有,保持现口径。
- 所有条件(含顶栏 `keyword`)之间为「且」;参数缺省或为空即不过滤该项。
- 契约 `weiran4j/docs/01-架构与接口契约.md` §6.2 先于代码更新;前端 `web/src/types/api.ts` 的 `UserQuery` 手动同步。
- 前端高级筛选面板按设计稿放出:用户名、用户 ID、手机号、邮箱、所属部门、角色、状态、性别、创建时间、最后登录时间。
- 新条件进入「已选条件」标签,显示可读值(角色名、性别名、日期范围),可逐个删除。
- 并入上一轮未提交的搜索栏改造(见澄清 #6)。
- 关闭 `openspec/state/bizs/sys_user.md#08`,同步 `sys_user.md` 的列表 / 筛选说明。

### 明确不做

> 「不做」比「做」更能防止 subagent 自行扩大范围。写具体,不要写「其他暂不考虑」。

- 不做「是否启用」字段(与状态同义)。
- 不做角色多选、用户名 / 手机号 / 邮箱的模糊匹配(模糊找人继续用顶栏 `keyword`,其口径不变)。
- 不改表结构、不加索引、不新增 Flyway 脚本(所需列与 `sys_user_role.role_id` 索引均已存在)。
- 不改列表排序(仍按 `id` 升序)、不加导出、不加「展开树状」按钮。
- 不改其它列表页(角色、部门、日志等)的搜索栏。
- 不改 `GET /api/users/options`、用户增删改接口与 `UserView` 返回结构。

### 本次不决定(留给后续 change)

- 大数据量下这些条件是否需要额外索引(`email`、`phone`、`created_at`、`last_login_at` 目前无索引);后台管理量级下暂不处理。
- 其它列表页是否接入同样的高级筛选面板。

## 验收标准

> 可判定真假的陈述。「体验更好」不是验收标准,「列表首屏 < 1s」是。
> **逐条编号 `AC-N`** —— L8 校验要按编号逐条回指,没有编号就只能整体估。

- [ ] AC-1 `GET /api/users` 传用户名参数时,只返回 `username` 与之完全相等的用户(去首尾空白后比较);传 `ali` 不返回 `alice`。
- [ ] AC-2 传用户 ID 参数时,只返回该 ID 的用户;ID 不存在时返回空列表且 `total=0`,不报错。
- [ ] AC-3 传手机号、邮箱参数时,分别只返回 `phone`、`email` 完全相等的用户。
- [ ] AC-4 传角色 ID 参数时,只返回在 `sys_user_role` 中拥有该角色的用户;每个用户只出现一次,`total` 与去重后的条数一致。
- [ ] AC-5 传性别参数时,只返回 `gender` 等于该值的用户;传 `male/female/unknown` 以外的值返回业务错误 `40000`。
- [ ] AC-6 创建时间范围、最后登录时间范围为闭区间:边界时刻的记录被包含;只传开始或只传结束时按单边过滤;
      最后登录时间为空的用户在传了最后登录时间范围时不被返回;时间格式非法返回 `40000`。
- [ ] AC-7 多个条件(含 `keyword`、`status`、`departmentId`)同时传时取交集;不传任何新参数时,结果与本 change 前完全一致。
- [ ] AC-8 契约 §6.2 列出全部查询参数及其匹配口径,与后端实现一致;`web/src/types/api.ts` 的 `UserQuery` 与契约字段一一对应。
- [ ] AC-9 前端高级筛选面板默认收起,展开后按设计稿顺序依次为:用户名、用户 ID、手机号、邮箱、所属部门、角色、状态、性别、创建时间、最后登录时间;
      点「搜索」后发出的请求包含已填写的各项参数。
- [ ] AC-10 已生效的每个新条件在「已选条件」中显示为一枚标签,值为可读文本(角色显示角色名、性别显示字典名称、时间显示「开始 ~ 结束」日期);
      点 × 后该参数从请求中移除并回到第 1 页,面板中对应控件同步清空。
- [ ] AC-11 L7 三闸门(后端 `check`、前端 test / lint / build)全绿,且有覆盖 AC-1~AC-7 的后端测试与覆盖 AC-9~AC-10 的前端测试。
- [ ] AC-12 `openspec/state/bizs/sys_user.md#08` 移入 changelog 标为已解决,并注明由本 change 关闭。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 单字段匹配方式 | 精确匹配 | 模糊包含 | 用户决策:高级筛选用于按已知值定位;模糊找人已有顶栏 `keyword` |
| 时间范围粒度 | 按天 | 精确到秒 | 与设计稿「开始日期 → 结束日期」一致;参数格式仍沿用契约,不新造日期格式 |
| 角色筛选 | 单选 | 多选任一命中 | 与设计稿一致,参数与标签都更简单 |
| 未提交的搜索栏改造 | 并入本 change | 先单独提交 | 用户决策;代价是 L9 diff 同时包含两部分,verify 中需分别说明 |

# Proposal

## Why

- 当前只有包内 Vitest 与后端集成测试，缺少统一登记、执行、复核和恢复真实 API/E2E 测试的入口。
- 用户指定复用 kr-alang-mono4j 的 tests；源框架已有严格证据管理与离线回归，但认证和业务绑定不能直接运行。
- 目标是在本项目获得可维护、可复核的系统级测试流程，清楚区分离线、合成和真实业务覆盖。需求见 interview.md，事实见 explore.md。

## What Changes

- 新增：tests 工作流框架、7 条系统流程、离线及合成回归、根命令与测试文档。
- 改造：源会话管理为当前 Cookie/CSRF 协议，健康与鉴权用例使用现有数字错误码；CI 增加独立离线检查。
- 复用：源 CLI、声明/注册表、AST 检查、批次、证据复核、脚手架、维护、会话恢复机制；保留当前包内测试。
- 不做：合同/返利/STS 业务，旧 test-flows 执行器，生产认证语义和数据库修改。

## Scope

### In Scope

- tests/ 通用能力与本项目系统流程，根工程脚本/依赖/CI，docs 导航及说明，测试现状记录。

### Out of Scope

- 不复制 test-flows/、源项目 .local/、.artifacts/、账号、浏览器缓存、历史证据和真实业务数据。
- 不新增合同、返利、STS、独立 Actuator 服务或认证兼容接口。
- 不改业务登录/登出语义，不为测试递增用户 token_version，不创建种子账号或修改密码策略。
- 不自动启停操作者已有服务，不自动推送或发布。

## Capabilities

| 能力 | delta 操作 | 说明 |
|---|---|---|
| `test-workflows` | ADDED | 长期管理 API/E2E/Bruno 流程、认证上下文、证据、执行、复核与恢复。 |
| `continuous-integration` | MODIFIED | 在既有门禁之外增加测试流程离线检查。 |

## Dependencies

- 根 pnpm 集中加入源项目已使用的 Playwright 1.65.0、Bruno CLI 4.3.0、TypeScript 6.0.3 与 @types/node 24.19.0，更新本仓唯一锁文件，不复制源锁文件。
- 测试 CLI / 新 CI job 使用 Node 24；保留现有前后端工具链与命令。Chromium 仅在浏览器回归和真实 E2E 时需要。
- 真实系统流程需要操作者预先启动本项目 5200/5202，认证流程需要明确提供的本地专用账号；不依赖源项目运行环境。
- 无数据库迁移、业务后端修改或页面设计变更。

## Risks

| 风险 | 触发场景 | 应对方案 |
|---|---|---|
| 认证协议混用 | 旧路径/字符串 code/localStorage 主体遗留 | session/browser/fixture/doctor/Bruno 同步适配并回归。 |
| 假清理 | 套用源 JWT 吊销断言 | 明确只清 Cookie/缓存，报告残留令牌自然到期的边界。 |
| 敏感信息留证 | 认证失败调用日志、trace、storageState | 固定错误文本，普通证据禁写凭据，私有文件最小权限。 |
| 真实覆盖误报 | 缺服务或账号 | doctor 明确失败；独立记录离线、合成与真实结果。 |

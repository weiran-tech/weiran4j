## 边界

### 要做

- 在 BCrypt 前原子预占尝试额度，账号/IP 独立保护，锁屏按用户保护，超限返回稳定 429 业务码；窗口恢复、并发和重启一致。
- 编辑版本独立于 token_version；旧版本更新及关系覆盖原子失败，前端保留草稿、明确冲突、主动重载后再编辑。
- 修正现行工作流注入的技术事实与本机执行命令，维护项目规则/模板镜像关系，验证 CLI 输出。
- 同步 OpenAPI/TS 类型、docs 交互演示、部署说明、现状追踪和必要追加迁移。

### 明确不做

- 不引入 Redis、外部认证服务、永久锁号、验证码产品或跨所有业务的通用幂等平台。
- 不迁移短信/MFA/绑定挑战状态，不处理跨会话授权刷新和权限缓存广播。
- 不改操作审计的可靠性等级，不处理 OpenAPI 全局包络适配或自动生成前端 SDK。
- 不批量重写历史归档、改变 CP/SL/WT 等规则含义，或放宽现有门禁。
- 不把登录、令牌吊销、偏好、收藏等独立原子字段更新强行纳入编辑冲突协议；删除保留现有确认语义。

### 本次不决定(留给后续 change)

- 短信/MFA 的多实例共享状态、其他会话授权同步分别保留 artifact.md#25/#26。

## 验收标准

- [ ] AC-1 账号/IP 达阈值后，在 BCrypt 前拒绝；已知/未知账号统一保护，窗口到期恢复，成功尝试也计额度且不能清空 IP 桶；锁屏 5 次/5 分钟，429 不清会话。
- [ ] AC-2 至少两个用例实例共用 MySQL 时并发不能超发额度，重启不清额度，存储异常失败关闭；过期键自动清理，容量到顶不能靠淘汰未过期计数绕过。
- [ ] AC-3 同一用户/角色的相同 version 两次更新只允许一次成功；冲突返回稳定 409，字段/角色/菜单关联与令牌版本不发生半提交。
- [ ] AC-4 角色编辑与授权集合共用版本；个人资料与管理员编辑互相检测冲突；登录/偏好/收藏不会导致编辑版本变化；重叠字段的其他定向补丁推进版本。
- [ ] AC-5 前端冻结草稿对应版本，后台刷新不得自动更新提交版本；冲突保留输入、禁重复提交，明确确认后重载，重载失败保留草稿；成功保存保持原关闭保护。
- [ ] AC-6 docs 使用本地数据复用真实组件/逻辑演示正常、保存中、限流、冲突、重载成功/失败、禁用与权限变化，不依赖生产服务。
- [ ] AC-7 实际 openspec instructions 的 context/instruction/template 与当前 Java/Spring/Flyway/动态菜单/数字 0 契约一致；故意注入已废止断言会转红，正常历史说明不误报。
- [ ] AC-8 只追加新迁移，旧数据库与新空库均可升级；缺 version 请求不能绕过；全部 L7、docs 构建和 OpenSpec 检查通过。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 节流计数 | BCrypt 前按尝试计数，MySQL 原子预占 | 校验失败后才计数、进程 Map | 并发失败完成前也需限流，重启/多实例不能重置保护；成功亦占额度须明确告知 |
| 并发协议 | 必填版本 CAS，冲突由人确认重载 | 默认取最新版本、客户端自动重放 | 后两者会把旧草稿变成覆盖写 |
| 升级兼容 | 前后端同步发布，旧写客户端明确报错 | version 缺失兼容无条件写 | 缺失兼容会保留绕过入口 |
| 模板纠偏 | 当前注入链与小范围失效模式守卫 | 清理全部历史或全局禁词 | 保留可追溯历史，避免误伤历史警示文字 |

## 未决歧义

- 无；以上是待 L3 审阅的具体方案，不将建议阈值伪装成用户已选数值。

## 对下游的硬约束

- JDK 21、先 spotlessApply 后 check；CP-7 追加迁移，保持数字 0 与六位错误码。
- 必需版本是写协议变更；上线必须同步前后端，刷新旧页面，禁止默认 version=0 或自动补最新版本。
- 工作区原有稳定改动保留；单工作区串行，不发起并行 agent。

# Proposal

## Why

密码认证每次直接执行 BCrypt，缺少统一尝试边界；用户/角色和授权集合维护不能识别旧草稿覆盖；现行工作流提示词仍含已废止的技术契约。用户选择 kaizen 审查的 1、2、5 项，见 interview.md。

## What Changes

- 新增密码/锁屏认证尝试节流，使用可信 IP、共享原子持久化与可配置窗口，超限与存储故障均不继续密码验证。
- 用户、角色及授权集合增加编辑版本前提；保护与个人资料的重叠写入，冲突保留输入并由用户确认重载。
- 修订现行 schema/config/templates，补充具体废止事实的防回退守卫和真实 CLI 输出验证。
- 复用既有关闭保护、查询恢复、可信 IP、MySQL 与五层装配；同步 OpenAPI 声明、TS、docs 演示、部署与状态文档。

## Scope

### In Scope

密码认证与锁屏校验、管理编辑及重叠资料更新的版本协议、现行提示词注入链、上述边界的前端反馈与 docs 演示。

### Out of Scope

- 不引入 Redis、外部认证服务、永久锁号、验证码产品或跨所有业务的通用幂等平台。
- 不迁移短信/MFA/绑定挑战状态，不处理跨会话授权刷新和权限缓存广播。
- 不改操作审计的可靠性等级，不处理 OpenAPI 全局包络适配或自动生成前端 SDK。
- 不批量重写历史归档、改变 CP/SL/WT 等规则含义，或放宽现有门禁。
- 不把登录、令牌吊销、偏好、收藏等独立原子字段更新强行纳入编辑冲突协议；删除保留现有确认语义。

## Dependencies

- JDK 21、现有 MySQL 8 与 Spring 事务，不新增 Redis/第三方库。
- 前后端同步发布写协议；旧客户端缺版本明确拒绝，不能降级无条件写。
- docs/page-states.md 及现有本地 React 挂载机制承载演示。
- 框架和流水线共享层串行完成；校验依据仓库当前规则，不依赖本次尚未修正的旧模板事实。

## Risks

| 风险 | 应对 |
|---|---|
| MySQL 准入协调增加认证开销 | 计数短事务先提交，BCrypt 在外执行；容量与锁等待有界 |
| 新 version 字段导致旧前端无法保存 | 同步发布、显式缺版本校验、升级说明 |
| 新缓存版本配旧草稿 | 将草稿基准与版本绑定，确认重载后一起更换 |
| 模板检查误伤历史解释 | 只扫描实际注入源的废止断言，正常说明有回归用例 |

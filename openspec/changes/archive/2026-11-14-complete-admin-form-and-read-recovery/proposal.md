# Proposal

## Why

- 背景：用户要求处理本轮 kaizen 审查的全部三项 P2，来源见 interview.md。
- 业务目标：减少编辑内容意外丢失，让读取失败可以被识别和恢复。
- 当前问题：四类编辑弹窗直接关闭；六类列表缺少持续失败反馈；操作日志详情首次失败仍转圈。

## What Changes

- 将现有表单关闭保护扩展到角色、菜单、字典和字典项。
- 为角色、菜单、字典及字典项、登录日志和操作日志提供一致查询反馈和重试。
- 操作日志详情区分加载、失败、可读缓存与成功。
- 复用 useFormCloseGuard、ListFeedback、ListEmptyState 和 QueryReadiness；同步 docs 交互演示与回归测试。

## Scope

### In Scope

- interview.md 的 AC-1 至 AC-6，以及对应现状条目关闭。

### Out of Scope

- 不处理 P3 内置角色状态选项约束。
- 不扩展个人中心、系统配置、外部身份等其他表单的关闭保护。
- 不改后端接口、数据库、权限码、菜单、认证或全局重试策略。
- 不提交或推送工作区原有的任务文档、部署文档与批处理迁移改动。

## Dependencies

- 产品/设计：既有 kaizen 结论与本次明确 P2 范围，L3 审阅 design。
- 后端/数据库/定时任务/运维配置：无依赖及变更。
- 前端：复用现有公共组件，查询 key 和 hook 协议保持稳定。
- 测试：vitest + jsdom；实际浏览器验证 docs 与弹窗状态；JDK 21 执行 project.json 门禁。

## Risks

| 风险 | 触发场景 | 应对方案 |
|---|---|---|
| 成功保存也确认放弃 | 混用关闭入口 | 区分主动关闭和保存成功直接关闭 |
| 数据丢失或误判为空 | 重试清空缓存、按长度判错 | 保留查询缓存，仅成功查询呈现空态 |
| 演示与真实行为不符 | docs 复制判定代码 | 复用实际 guard 与呈现组件，业务页回归验证接线 |

# Design

## Context

- 来源：interview.md 的 AC-1 至 AC-6；explore.md 已确认已有公共能力可复用。
- 前端增量修改：四类弹窗、六类列表、一个日志详情，以及 docs 演示。
- 保留既有接口与权限；不涉及 P3 内置角色状态约束，不引入全站离开页面拦截。
- 主规格 FR-014、FR-015 的原始标题含“用户”，为保持稳定需求标识沿用标题，在正文明确扩展适用范围；原有用户场景全部保留。

## Architecture

既有页面通过 TanStack Query 获取数据，由实际查询状态驱动 ListFeedback、ListEmptyState 和 QueryReadiness；关闭动作和提交动作由既有 useFormCloseGuard 统一互斥。docs 挂载实际公共对象，查询与保存使用本地模拟。单执行单元串行，不改变应用外壳与路由。

## Data Flow

1. 弹窗主动关闭先比较当前值与初值，无变更直接关闭，有变更确认放弃；继续编辑保留内存值。
2. 提交先进入 guard 互斥区，再校验与调用既有 mutation；失败释放互斥且保留草稿，成功直接关闭，不经过放弃确认。
3. 查询首次读取显示加载；失败显示对应区域错误与重试；成功空结果才显示空态。
4. 有缓存时刷新失败保留数据并提示“当前显示上次加载的数据”；重试仅 refetch 当前查询，不重置筛选、分页与选中状态。
5. 日志详情遵循同一读取流程，是否显示详情由 data 是否可用决定，不能以无 data 等同加载中。

## 跨模块契约变更(DS-1)

| 对象 | 动作 | 消费方 |
|---|---|---|
| framework 错误码 / 包络 / 分页 | 无 | 后端与前端协议稳定 |
| 公共组件与 hook | 复用现有协议 | 页面与 docs |

如需为复用详情呈现提取组件，限定为前端内部纯呈现协议：只接收查询状态、数据与重试回调，不向组件内迁入请求或权限策略，并登记组件清单。

## API Design(DS-2)

沿用角色、菜单、字典和日志既有 GET 与写接口、参数、权限及数字 code=0 的包络，不新增路由，不改变 Controller / DTO。重试沿用已生效查询 key，保存体保持原有映射。

## Database Design(DS-3)

无表、索引、种子、Flyway 或菜单 id 变更；工作区原有兼容迁移不属于本次设计。

## 权限与已知缺口(DS-4)

| 项 | 设计 |
|---|---|
| 权限点 | 沿用既有创建、编辑、删除与日志读取权限，不因错误恢复放开权限 |
| 菜单挂载 | 无变更，沿用 sys_menu 驱动的既有路由 |
| 操作审计 | 不新增写接口，既有保存仍由后端记录 |
| 范围限制 | 不处理 P3 内置角色禁用选项；不扩展其他表单保护 |

数据范围、多租户、任务中心和审批不涉及。本地防重复提交仅保护单弹窗交互，不承诺跨会话写入幂等。

## 前端设计(DS-6)

### 编辑保护

角色、菜单、字典及字典项的取消、关闭按钮与 Esc 均走 guard.requestClose；校验和保存整个过程走 guard.submit。保存时取消禁用、关闭按钮隐藏、Esc 不生效，保存按钮显示等待状态；与用户编辑已有模式一致。失败不清空、不关闭，成功直接 onClose。无新增草稿持久化。

### 列表反馈

- 角色、登录日志和操作日志：表格前放持续错误提示；成功空列表按是否有已生效条件显示“暂无记录”或“没有匹配结果”，后者支持清空条件回第一页。
- 菜单树：错误提示与原地重试，成功空树显示无记录；不新增筛选或重置树展开状态。
- 字典主列表：保持 NavListPanel 的搜索、分页和项目操作；错误反馈属于左侧区域，加载与错误时不显示“暂无字典”。成功无匹配时提供清空搜索入口。
- 字典项：独立错误提示、刷新/重试入口与成功空态；重试不改变当前字典。主列表首次失败且没有可选字典时，右侧不显示误导性的“请选择字典”；成功后按原逻辑选中。
- 判断缓存是否存在使用 data 的可用性，不使用数组长度；空数组也是成功缓存。

### 操作日志详情

保留 SideSheet、已有字段及请求体格式化。复用 QueryReadiness 呈现加载和失败；可用 data 继续显示，首次失败没有无限 Spin；重试当前 ID，成功移除错误提示。必要提取纯详情呈现对象，以供实际页面和 docs 共用。

### docs 演示

在现有页面状态演示扩展编辑保护、列表反馈、日志详情三类场景，沿用 ClientOnly 与 Vue/React 挂载；演示复用 guard、ListFeedback、ListEmptyState、QueryReadiness 及需要的纯详情呈现对象。提供加载、空数据、首次失败、缓存刷新失败和重试控制；表单提供模拟保存成功/失败/延迟完成，以操作取消、Esc 和重复点击。全部使用本地数据，不导入真实 HTTP hook 执行业务请求。

### 现状追踪

解决 artifact.md#23/#24、sys_login_log.md#04、sys_operation_log.md#07；实现前认领，实现后原编号移至 changelog，同时更新相关模块现状说明。与本次无关的已知问题保持待办。

## Observability

- 页面错误提示持续可见，重试按钮给出等待反馈；不使用原始异常文本或堆栈。
- 不增加生产日志、埋点或告警系统；回归通过可见状态、请求次数、请求参数和保留数据断言。

## Test Plan

| 层级 | 范围 | 验证方式 |
|---|---|---|
| 四类真实弹窗 | AC-1、AC-2 / FR-015 | 无改动、有改动、继续/放弃、取消/关闭/Esc、延迟校验与保存、失败保留和成功关闭；使用真实 Semi Form |
| 六类列表 | AC-3、AC-4 / FR-014 | 逐类覆盖首次失败、原参数重试、缓存刷新失败、成功空结果；字典主从独立恢复，筛选清空回第一页，菜单树展开保留 |
| 日志详情 | AC-5 / FR-020 | 首次失败无无限加载，同 ID 重试，缓存刷新失败保留字段，成功恢复 |
| docs | AC-6 / FR-018 | 构建并用真实浏览器操作三个场景，验证无业务请求；查看窄屏与桌面提示、弹窗与字典布局 |
| 完整门禁 | 既定验证 | 先 JDK 21 spotlessApply，再逐条读取并执行 project.json 的 build/test/lint，证据留 exec/evidence；另跑 docs 构建和 OpenSpec 校验 |

不以源码字符串出现代替行为回归；只有最终代码产生的真实输出作为证据，不复用前次 change 的结果。
